# I. MISSION AND NONNEGOTIABLES

Implement the first authorized engineering unit of the SUN Multi-Orientation Typed Generative Compression Engine.

The long-term architecture contains four independent native orientations:

1. **Sefer Yetzirah** — 3 mothers, 7 doubles, 12 simples, plus explicitly modeled conditional states and the 231-gate possibility space.
2. **Western music** — interval-generation, diatonic/chromatic structures, modal transformations, exact ratios and register.
3. **Chinese music** — twelve lü, five tonal functions, pipe-length generation and modal reassignment.
4. **Indian music** — grāma/śruti/svara organization, mūrchanā, melakarta and separate documented numeric encodings.

These systems must eventually be evaluated against historical-linguistic baselines using minimum description length, typed operators, commutation tests, held-out observations and independent validation.

**DO NOT IMPLEMENT THOSE DOWNSTREAM SYSTEMS IN THIS ENGINEERING UNIT.**

The only authorized work is:

- G0: lossless historical/typological evidence architecture;
- G1: Sefer Yetzirah baseline compatibility;
- an empty, enforceably locked cross-orientation interface;
- tests, provenance records and verification reports necessary to establish G0/G1.

Preserve all established work. Do not overwrite a frozen baseline, reinterpret unresolved evidence as settled, or silently replace earlier architectures.

## Three governing rules

### Rule 1 — Lossless evidence preservation

Every normalized element must trace back to precisely the evidence from which it was derived.

Normalization may add interpretations, links and derived features. It must not destroy the original representation, merge competing claims, silently modify Unicode, or replace missing information with guesses.

### Rule 2 — Typed transformations

Distinguish:

- glyph identity;
- glyph representation;
- letter identity;
- letter name;
- phonetic value;
- phonetic realization;
- syllabographic value;
- ordinal position;
- generation order;
- observed pronunciation;
- inferred sound;
- graphical topology;
- historical transmission;
- proposed alignment;
- musical function;
- symbolic classification.

These are separate types or claims, not interchangeable strings.

### Rule 3 — Independent reconstruction

A candidate is not historically established merely because it completes a count, produces a short description, or uniquely fits one configured model.

Maintain separate verdicts for structural consistency, model preference, parameter identifiability and historical support.

No cross-orientation inference may influence G0/G1 native results.

# IV. G0 COMMON EVIDENCE DATA MODEL

- original script label;
- script-local ordinal;
- raw glyph;
- raw IPA entry;
- raw English approximation;
- whether a field was blank;
- exact source coordinates;
- original value strings.

A blank glyph position is not an attested missing letter.

- script_id;

- phonetic representation classification;
- derived claim references;
- attestation references.

Use immutable or defensively copied mappings. `frozen=True` on a dataclass is insufficient when nested dictionaries remain mutable.

Enforce stable uniqueness on `(source_artifact_id, script_id, local_ordinal)`.

## 4.4 Phonetic classifications

Use canonical enum names.

At minimum support:

- PHONEME_VALUE;
- LETTER_NAME;
- SYLLABOGRAM;
- VOWEL_SIGN;
- UNKNOWN_VALUE;
- SILENT_PLACEHOLDER.

A claim should contain:

- claim_id;
- subject_id;
- property;
- proposed value;
- epistemic status;
- evidence references;
- source locator;
