## What the models mean

The first letter-based **3 + 7 + 12 = 22** implementation is the stipulated **Sefer Yetzirah** partition. The separate SUN music-native taxonomy has three constructors, seven mechanisms and twelve relations. Western, Chinese, Indian grāma–śruti and melakarta models retain their own native rules; equal counts do not establish shared identities.

The canonical dataset preserves **15 scripts × 36 positions = 540**, comprising **381 supplied glyph positions and 159 blanks**. Unicode proxies, four unknown Etruscan readings, one unresolved Sabaic label, alternative readings, English letter names and Old Persian sign types remain distinct. Canonical features have an explicit missing-data mask and ordered phonetic sidecars. Historical glyph stroke topology is unavailable without suitable images; proxy character rendering is not epigraphic evidence.

The original-host record contains 112 passing project tests, the bounded G0/G1 checks, six original Sefer tests and exact original demonstration equality. These are archived execution receipts, not a fresh test result on your machine. The additive portable verifier rederives the canonical arrays and checks all 106 original requirement rows, writing a new receipt instead of changing those records.

The publication copy was checked separately in a clean analysis environment: 71 G0/G1 tests and six original Sefer tests passed, as did the portable derivation, 39 packaging/verifier tests and six browser startup checks. The [fresh full Node run](publication/verification/full-project-run.json) passed 116 of 118 tests; two source-fidelity checks fail because retained third-party source inputs are absent from the public copy. Full Node acceptance remains partial. These checks are separate from scientific completion.

G0/G1 are verified for their bounded engineering scope. Native musical/control calculations do not certify historical common ancestry. Historical model comparison is not evaluated; historical cross-orientation reconstruction remains locked. Remaining scientific dependencies are retained in the requirements register.

## Reproduce the portable check

Use Python 3.13 for the versions exercised during preparation:

```powershell
python -m venv .venv-analysis
.venv-analysis\Scripts\python -m pip install -r requirements-ariadne.txt
.venv-analysis\Scripts\python scripts\verify_abracadabra.py --output verification\portable-receipt.json
```

On macOS/Linux, use `.venv-analysis/bin/python`. That platform path is documented; only the actually reported platforms are verified. The verifier refuses to overwrite an existing receipt or protected inputs. Optional live Jev and Windows worker services require their separately documented runtime and model bootstrap; opening the workbenches does not invoke them.
