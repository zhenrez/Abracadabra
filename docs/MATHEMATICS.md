## Finite constraint evaluation

`evaluateCandidates(candidates, constraints, kernel)` checks every supplied candidate against every supplied constraint and retains per-constraint witnesses. A kernel includes an ID, version, SHA256, and source references. The module validates the supplied digest's shape and matches constraints to that digest. It does **not** independently read a source file, recompute the kernel's hash, resolve references in the archive, or establish its authority; the host must bind these records to preserved evidence.

Implemented predicates are exact equality, inequality, membership, exact rational ratio, distinctness, three-valued conjunction/disjunction, unresolved expressions, and custom expressions. These form a representation DSL, not the musical ontology. Missing assignments, missing references, mismatched kernels, undefined ratios, and unimplemented custom operators remain `unknown`. An explicit failed constraint remains a failure even when another constraint is unknown. Empty constraint sets provide no positive evidential support. Duplicate candidate or constraint IDs are rejected instead of silently merged.

The result distinguishes `admissible`, `rejected`, and `unresolved` **under the supplied constraints and candidate family**. It makes no global completeness assertion, probability estimate, truth adjudication, or canonical promotion. Multiple admissible candidates remain multiple. No authoritative W72 completion set or frozen SUN kernel was supplied to this module, and no actual SUN orientation result was computed. All test candidates are synthetic.

`dependencyGroups` preserve shared-source dependence without counting repeated statements as independent confidence votes. This applies the relation/unit distinction from Cryptography Research Skills to evidence accounting; it is not a cryptographic protocol, security proof, or claim that semantic correspondences have cryptographic independence.

## Geometry already implemented

`wheelAddress` preserves a half-open 720-degree generation coordinate, both constituent rotations, dial phase, and negative-phase boundaries. The 720-degree convention is retained from the user's specification; it is not inferred by this module. `wheelPoint` returns unresolved placement when radius or height is missing. No growth/rebound equation or 144,000 maximum-breadth boundary was invented.

`torusPoint` implements the ordinary ring-torus parameterization with finite radii satisfying `R > r > 0`. These standard formulas and the distinction between ring, horn, and spindle tori are documented by [Wolfram MathWorld](https://mathworld.wolfram.com/Torus.html). This is an optional three-dimensional projection; it does not establish a four-dimensional dynamical model, a spacetime interpretation, or that acoustic waveforms universally have torus topology.

`sierpinskiTetrahedron` constructs finite stages using four half-scale homotheties per stage. Depth is restricted to integers 0–7 for finite resource use. A depth `n` contains `4^n` cells, edge scale `2^-n`, and volume fraction `2^-n` relative to the root. Wolfram's [SierpinskiMesh documentation](https://reference.wolfram.com/language/ref/SierpinskiMesh.html) provides the corresponding standard three-dimensional construction. The software neither renders infinity nor establishes a Monad correspondence or a tesseract/dodecahedron derivation.
